本文把 **1.0「热词唤醒 + 纯语音问答」** 升级为 **2.0「双键菜单壳 + 异步分析 + 进节目即听的综合建议 + 结构化训练计划」**。  
固件、墨水屏 UI、任务队列与交互以本文为准。  
**节目级 Agent 策略（装包、分析方法、报告 Schema、废弃总 Agent）以《三节目策略》为准**；与旧「主教练 + SQL 子代理混合对话」冲突时，以三节目策略为准。

---

## 1. 升级一句话

用户在墨水屏上用 **两个物理键** 进入三个节目：

1. **单次分析**：定时同步出现新场次 → **后台已异步分析**；列表只显示分析中/已完成；点 ✓ 只读报告（不现场等模型）；
2. **趋势分析**：**不**在同步后预跑九档；点某一跨度 → **分析运行页**（正在分析中）→ 停留则完成后自动进详情；已有有效缓存可直进详情；
3. **综合建议**：进入即视为唤醒听麦（无热词）→ 语音采集 / 更新画像与目标 → 异步生成 **固定模板** 的训练计划 → 有计划后可翻页查看。

训练数字与分析结论仍由 NAS 侧 Agent + 本地 SQLite 完成；原始 Garmin 数据不出本地。

## 2. 相对 1.0 的核心变化

| 维度   | 1.0                      | 2.0                                                                 |
| ------ | ------------------------ | ------------------------------------------------------------------- |
| 入口   | 离线热词唤醒 → 直接对话 | 首页 / 休眠唤醒 → **主菜单三节目**                           |
| 交互   | 几乎纯语音               | **双键导航为主**；仅「综合建议」内持续语音                    |
| 分析   | 口语问答中临时查数       | **单次 / 趋势** 独立入口 + **异步任务** + 列表状态 icon |
| 计划   | 无固定结构输出           | **热身 / 主要 / 放松** 结构化多页计划                         |
| 画像   | 对话中零散采集           | **持久化**；再次进入展示已收集字段                            |
| 休眠   | 未系统定义               | B 双击回首页再休眠；休眠中 A 双击进主菜单                           |
| 屏形态 | 偏聊天长文               | 200×200 黑白、列表 / 宫格 / 字段模板                               |

不改动的约束（继承 1.0）：

- 原始运动数据仅存 NAS SQLite，不上传第三方 LLM；
- ASR / TTS 可走小智云端；LLM 仅接收提问 + 精简汇总；
- 库查询只读；内网鉴权；不把 NAS 暴露公网。

## 4. 双键全局规格

硬件假定：**A 键**为功能键，**B 键**为电源键（兼导航）。

### 4.1 默认手势表（全局，除非被覆盖态改写）

| 键          | 单击            | 双击                                     | 长按                  |
| ----------- | --------------- | ---------------------------------------- | --------------------- |
| **A** | 上一项 / 上一页 | **确定**                           | **返回上一级**  |
| **B** | 下一项 / 下一页 | **休眠**（先回首页再休眠，见 §5） | **开机 / 关机** |

说明：

- 「项」：列表行、主菜单行、趋势宫格焦点等一维焦点序列中的节点。
- 「页」：训练计划等多页内容的翻页；与「项」共用上下键语义，由当前屏解释。
- 无上一项 / 无下一项 / 无上一页 / 无下一页时：**静默无反馈**（不震动、不弹错误页，除非后续单独加弱提示）。
- 双击与长按的时间阈值由固件统一配置（建议：双击间隔 ≤ 400ms；长按 ≥ 1.5～2s；开关机长按可略长于返回，避免误触——具体数值实现时标定）。

### 4.2 焦点模型（白话）

**焦点** = 当前高亮控件；**A 双击「确定」作用在该控件上**。

| 页面类型     | 焦点在哪                           | A 双击含义                                                     |
| ------------ | ---------------------------------- | -------------------------------------------------------------- |
| 主菜单       | 某一菜单行                         | 进入该节目                                                     |
| 单次分析列表 | 某一场次行                         | 仅当该行 **已完成（✓）** 时进入详情；分析中无效         |
| 趋势分析宫格 | 某一跨度格                         | 点选 → 分析运行页并触发该跨度；已成功可直进详情；运行页轮询至完成 |
| 综合建议     | **底部 CTA「建议训练计划」** | 仅当 **已有可用计划** 时进入计划首页；无计划或生成中无效 |
| 计划多页     | 整页（无行焦点）                   | 一般无「确定」业务；翻页用 A/B 单击                            |

### 4.3 覆盖态：综合建议「正在聆听」

进入综合建议并处于 **正在聆听** 时，**焦点仍在 CTA**，但 A 的单击 / 双击被临时改写：

| 手势          | 聆听中含义                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| A 单击        | **打断**当前聆听（结束拾音，不提交或按产品定为丢弃本段——实现默认：打断=停止听，已识别文本是否提交见 §7.4） |
| A 双击        | **确认**本轮说话结束，进入后续「正在分析」等流水线                                                            |
| A 长按        | 仍 **返回上一级**（退出综合建议）                                                                             |
| B 单击        | 仍「下一项」（本页通常无下一项 → 静默）                                                                            |
| B 双击 / 长按 | 仍休眠 / 开关机                                                                                                     |

「正在分析」「正在回复」是否允许 A 单击打断生成或 TTS：建议允许（与口语产品一致），实现时与聆听打断共用「取消当前轮」逻辑。

## 5. 电源、首页与休眠

### 5.1 开关机

- **B 长按**：在关机态 → 开机进入首页（或直接进主菜单，若实现选择「开机进菜单」须在固件配置中写死一种，默认：**开机到首页**，再由用户操作或自动短时进入菜单——推荐开机停首页，A 双击或超时进主菜单；若需简化可开机直达主菜单）。
- **B 长按**：在开机态 → 关机（可二次确认；若不做确认，须保证与「返回」长按不在同一键）。

> 本文约定：**返回 = A 长按**，**开关机 = B 长按**，二者不冲突。

### 5.2 休眠（B 双击）

无论当前在哪个业务页：

1. 立即停止听麦 / TTS（若有）；
2. **先回到首页**；
3. 再进入休眠（低功耗、墨水屏可保留首页画面或熄扫描，由硬件决定）。

### 5.3 从休眠唤醒

- 休眠中 **A 双击**：确认唤醒 → **进入主菜单**（不是综合建议，也不是上次深链页）。
- 休眠中误触单击：可忽略或仅亮屏仍停在休眠策略（实现默认：单击忽略，仅双击 A 唤醒进菜单）。

### 5.4 与「进综合建议即唤醒听麦」的关系

- **系统休眠唤醒** ≠ **语音会话唤醒**。
- 只有用户从主菜单 **确定进入「综合建议」** 后，才开始听麦（进节目 = 语音唤醒）。
- 离开综合建议（A 长按返回）或 B 双击休眠时，**必须关麦**。

## 6. 节目一：单次分析

### 6.1 目标与时序（对照设计稿「单次分析」列表）

用户打开列表时，报告应 **多数已算完**；交互是「翻已出炉的结果」，不是「点一下再等分析」。

| 步骤 | 谁做 | 状态 / UI |
|------|------|-----------|
| 1. 每天定时同步 Garmin → 本地库 | NAS / GarminDB | — |
| 2. 新游泳写入后入队分析 | Worker | **分析中**（转圈） |
| 3. `session_analysis_agent` 跑完，报告入库 | Worker | **已完成**（✓） |
| 4. 表盘拉列表：日期、距离、SWOLF + icon | 固件 | 两态 icon |
| 5. 用户对 ✓ 确定 | 固件 | **只读**已存报告；不再调模型 |

错误理解（已否定）：用户点条目 → 才开始分析 → 盯着屏等几十秒。

### 6.2 选项页（已设计，节点 `KCLJQ`）

- 展示近期场次卡片：日期、距离、SWOLF。
- **每条有且仅有两种状态**：
  - **分析中**：右上角转圈；
  - **已完成**：右上角 ✓。
- 新场次同步后：**自动入队**并显示转圈，不得空白无 icon。
- 转圈 → 禁止进详情；✓ → A 双击进详情（读库）。

### 6.3 二级详情页（延后）

依赖「具体分析方法 / 模板」定稿后再设计版式。候选输入见 `docs/agent-knowledge-cards-v1/`（效率、耐力、稳定性、负荷、趋势等）。
在方法未定前，**后端仍可先跑通异步任务与状态字段**，详情 UI 用占位即可。

### 6.4 列表即「历史结果入口」

不单独做「历史」菜单。单次分析列表同时承担：

- 选场次；
- 看哪些报告已完成 / 仍在跑；
- 回看已完成报告（✓ → 详情）。

## 7. 节目二：趋势分析

### 7.1 选项页（已设计）

3×3 跨度：1周、2周、3周、1个月、2个月、3个月、6个月、9个月、1年。
焦点在格点上，A/B 单击按一维顺序移动（行优先：左→右，再下一行），无更多项时静默。

### 7.2 点选触发（与单次不同）

同步后 **不** 预计算 9 个跨度（浪费算力）。交互：

1. 九宫格点某跨度（如「1个月」）→ `POST /trends/{span}/analyze`；
2. 若返回 `cached=true` / `can_open=true`：**跳过分析中页**，直接 `GET .../report` 进详情（不跑模型）；
3. 否则进入 **分析运行页**（「趋势-分析中」），轮询 `GET /trends/{span}/status`，完成后进详情；
4. 窗口内 **0 场** → 「趋势-无数据」，不进详情翻页；
5. **结果保存**：成功报告按跨度入库，并带窗口数据指纹；同一跨度在场次未变时再次点选只读缓存；
6. **作废时机**：`after-sync` 仅在有**新场次入队**时清空趋势缓存；或点选时发现该跨度指纹已变则重跑。

### 7.2.1 趋势详情翻页（设计稿，对齐 `trend_bundle_v1`）

| 页 | 设计稿名 | 数据来源 |
|----|----------|----------|
| 状态 | 趋势-无数据 / 趋势-分析中 | 场次数=0 / status=analyzing |
| 1 | 趋势-概览 | `pages[overview]` + headline |
| 2 | 趋势-进步 | `pages[progress]` |
| 3 | 趋势-负荷 | `pages[load]` |
| 4 | 趋势-下一步 | `pages[next_step]` + `headline.one_liner` |
| 5–7 | 趋势-SWOLF / 配速 / 距离 | `charts.*.points` + `note` |

宫格可选显示 ✓（本跨度仍有有效缓存）；无缓存的格无需预先转圈。

### 7.3 实现备注（非否决）

九档对双键较重；若后期发现难用，可减档而不改状态机。减档属产品迭代，不阻塞 2.0 落地。

## 8. 节目三：综合建议

### 8.1 定位

1.0 语音教练的 **节目化衍生**：不靠热词，**进入本页 = 开始语音会话**；最终交付物除口语外，还有 **可翻页的结构化训练计划**。

### 8.2 页面结构

| 区域 | 内容                                                                                |
| ---- | ----------------------------------------------------------------------------------- |
| 左上 | Ian Logo                                                                            |
| 右上 | **状态文案**（三态互斥，见下）                                                |
| 中部 | **正文区**：引导语 / 档案摘要 / 当前语音回合摘要 / 回复摘要（同一块区域切换） |
| 底部 | CTA「建议训练计划」+ 右侧状态 icon（生成中转圈 **或** 已完成 ✓，互斥）       |

### 8.3 右上角状态机

| 状态文案    | 含义                         | 听麦 | CTA            |
| ----------- | ---------------------------- | ---- | -------------- |
| 正在聆听... | VAD / 录音中                 | 开   | 依是否已有计划 |
| 正在分析... | ASR 后 Agent / 查数 / 写计划 | 关   | 生成中则不可点 |
| 正在回复... | TTS 或屏上展示回复           | 关   | 同上           |

「正在聆听」结束条件：

1. **静音超时**（VAD 尾点）；或
2. **聆听中 A 单击打断**；或
3. **聆听中 A 双击确认**（主动结束本轮并提交）。

打断与确认的差异（默认实现）：

- **打断（A 单击）**：停止录音；本段不完整内容默认 **不提交**（或提交已识别部分由配置开关，默认不提交）。
- **确认（A 双击）**：停止录音并将本轮文本送入 Agent 流水线 → 进入「正在分析」。

### 8.4 正文区内容策略

| 情境                  | 正文显示                                                     |
| --------------------- | ------------------------------------------------------------ |
| 首次进入、无持久画像  | 引导：告知可说年纪、身高、体重、性别、训练目标等             |
| 再次进入、已有画像    | 展示已收集的年纪、身高、体重、性别、训练目标等（可换行压缩） |
| 语音回合中 / 刚确认后 | 用同一区域显示本轮用户话摘要或教练短回复（替代长引导）       |

语音回合 **不另开聊天气泡流**，只刷新这一块，适应墨水屏。

### 8.5 画像持久化

- 存储位置：NAS 侧运动员档案（与现有 `save_profile_fields` 等工具对齐）。
- 字段至少：年龄、身高、体重、性别、训练目标（可扩展 CSS、伤病史等，屏上不必一次全亮）。
- 第二次及以后进入综合建议：**先渲染档案摘要**，再进入聆听，避免每次重问。
- 用户用语音说「改一下体重」「目标改成减脂」等 → Agent 更新档案 → 正文区刷新。

### 8.6 CTA「建议训练计划」与语音的关系

| 计划状态 | CTA 外观                                                                         | A 双击（非聆听覆盖时）         |
| -------- | -------------------------------------------------------------------------------- | ------------------------------ |
| 无计划   | 不可点击（灰态或保持黑底但双击无效；推荐视觉上区分，墨水屏可用空心框表示不可点） | 无效                           |
| 生成中   | 显示转圈；不可点击                                                               | 无效                           |
| 已有计划 | 可点击；可显示 ✓                                                                | **进入计划「热身」首页** |

- **重新生成**：不增加按键手势；用户 **语音说明**（如「按恢复周重新做一份计划」）即可；生成中 CTA 再变转圈不可点，完成后可再次进入。
- 聆听中 A 双击是「确认说话结束」，**不是**「打开计划」；打开计划仅在非聆听（或分析/回复结束回到可操作态）且 CTA 可点时，A 双击生效。

### 8.7 计划也异步

与单次 / 趋势同一思想：生成计划不阻塞用户必须盯着本页。用户可 A 长按返回主菜单；后台继续；再次进入综合建议时 CTA 显示转圈或 ✓。

## 9. 结构化训练计划（渲染契约）

后台生成字段；表盘 **按模板渲染**，不写死某一套课表。详尽排版见设计稿 note「训练计划排版说明」，此处为实现摘要。

### 9.1 分页

- 一页只显示一个板块：**热身 / 主要 / 放松**。
- **休息不单独成页**，写在所属板块内。
- 「主要」重复 N 次时，休息表示 **每次之间的间隔**（如 `休息：0:15`）。
- 一块放不下 → **续页**：标题与重复次数保留；非末页底部下三角。

### 9.2 字段与显示顺序

自上而下：

1. 标题（热身 / 主要 / 放松），20px 加粗；下划线分隔；
2. 重复：`N 次`（黑底白字，标题右侧）；无则省略；
3. 距离 → 泳姿 → 类型 → 器材 → 注释 → 休息。

规则：

- 值为「无」或注释为空 → **整行不显示**；
- **不显示强度目标**；
- 界面文案用「类型：」，不用「训练类型」；
- 注释：标签一行，正文下一行，最长 200 字；
- 泳姿枚举：自由泳、蛙泳、仰泳、蝶泳、选项、混合泳 (IM)、IM/趟、逆序个人混合泳 (RIMO)、混合泳 等；
- 类型枚举：踢动、划水、分解动作；
- 器材枚举：脚蹼、浮板、手蹼、夹水器、呼吸管。

### 9.3 键位

- A 单击：上一页；B 单击：下一页；尽头静默。
- A 长按：返回综合建议（或返回主菜单——默认 **返回综合建议**）。
- B 双击：回首页并休眠（全局）。

### 9.4 计划对象形态（与 Schema 一致）

实例须能通过 §9.5 的 JSON Schema 校验。示意：

```json
{
  "sections": [
    {
      "kind": "warmup",
      "repeat": null,
      "distance_m": 240,
      "stroke": "自由泳",
      "drill_type": null,
      "equipment": null,
      "note": "轻松自由泳",
      "rest_s": null
    },
    {
      "kind": "main",
      "repeat": 3,
      "distance_m": 120,
      "stroke": "自由泳",
      "drill_type": "分解动作",
      "equipment": "浮板",
      "note": "30米打腿 + 30米单臂 + 60米配合",
      "rest_s": 15
    },
    {
      "kind": "cooldown",
      "repeat": null,
      "distance_m": 180,
      "stroke": "选项",
      "drill_type": null,
      "equipment": null,
      "note": "放松游",
      "rest_s": null
    }
  ]
}
```

说明：

- `plan_id` / `created_at` 由 **服务端写入**，不必也不应放进模型 structured output（避免模型瞎编 ID）。
- 前端按字数拆「主要 / 主要续」等续页，**不**要求模型输出续页边界。
- `null` 或空注释 → 渲染层整行省略（与 §9.2 一致）。

### 9.5 强制：用 JSON Schema 约束 Agent 结构化输出

**决议：后续凡「出训练计划」，必须用 LangChain Structured output + JSON Schema，禁止从自由文本里正则/手写解析计划。**

官方说明：[Structured output](https://docs.langchain.com/oss/python/langchain/structured-output)。

#### 9.5.1 为何单独一条流水线

当前口语主教练用 `create_deep_agent`（见 `agent/src/coach_agent.py`），适合多轮工具与口语。  
**出计划**应是异步 Worker 里的 **专用调用**（推荐 `langchain.agents.create_agent` + `response_format`），输入为档案 + 近期训练摘要 + 用户诉求，输出只进 `structured_response`，再入库供墨水屏渲染。

不要让主教练在同一轮回复里「边聊天边夹一段 JSON」。

#### 9.5.2 策略选择（LangChain）

| 方式 | 用法 | 说明 |
|------|------|------|
| `ProviderStrategy(schema)` | 提供商原生 structured output | 最稳；schema 可为 Pydantic / dataclass / TypedDict / **JSON Schema dict** |
| `ToolStrategy(schema)` | 用 tool calling 模拟结构化输出 | 模型无原生 structured output 时用（硅基流动等需实测后二选一） |
| 直接传 `type[Schema]` | 自动选 Provider 或 Tool | **仅适用于类型对象**；**JSON Schema 字典不能裸传** |

官方警告：**JSON Schema 字典必须包在 `ProviderStrategy` 或 `ToolStrategy` 里**；裸传给 `response_format` 不会被自动识别。  
JSON Schema 顶层 **必须** 含 `title` 与 `description`。  
若提供商支持，可设 `ProviderStrategy(..., strict=True)`（需 `langchain>=1.2`）。

结果读取：`result["structured_response"]`（dict）；校验失败则任务 `failed` 或按 ToolStrategy 的 `handle_errors` 重试，**不得**把半截文本当计划上屏。

#### 9.5.3 训练计划 JSON Schema（实现以此为准）

可落在例如 `agent/src/schemas/swim_plan.schema.json`（路径实现时确定），内容与下表一致：

```json
{
  "title": "SwimTrainingPlan",
  "description": "游泳课结构化训练计划：热身、主要、放松板块列表，供墨水屏按模板渲染。",
  "type": "object",
  "additionalProperties": false,
  "required": ["sections"],
  "properties": {
    "sections": {
      "type": "array",
      "description": "按上课顺序的板块；通常含 warmup、main、cooldown。",
      "minItems": 1,
      "items": { "$ref": "#/$defs/section" }
    }
  },
  "$defs": {
    "section": {
      "type": "object",
      "additionalProperties": false,
      "required": ["kind"],
      "properties": {
        "kind": {
          "type": "string",
          "description": "板块类型",
          "enum": ["warmup", "main", "cooldown"]
        },
        "repeat": {
          "type": ["integer", "null"],
          "description": "重复次数；无则 null。主要组常用。",
          "minimum": 1
        },
        "distance_m": {
          "type": ["number", "null"],
          "description": "本板块距离（米）；无则 null",
          "minimum": 0
        },
        "stroke": {
          "type": ["string", "null"],
          "description": "泳姿；无则 null",
          "enum": [
            "自由泳", "蛙泳", "仰泳", "蝶泳", "选项",
            "混合泳 (IM)", "IM/趟", "逆序个人混合泳 (RIMO)", "混合泳",
            null
          ]
        },
        "drill_type": {
          "type": ["string", "null"],
          "description": "训练类型（界面显示「类型：」）；无则 null",
          "enum": ["踢动", "划水", "分解动作", null]
        },
        "equipment": {
          "type": ["string", "null"],
          "description": "器材；无则 null",
          "enum": ["脚蹼", "浮板", "手蹼", "夹水器", "呼吸管", null]
        },
        "note": {
          "type": ["string", "null"],
          "description": "注释正文；空或 null 则不显示。最长 200 字。",
          "maxLength": 200
        },
        "rest_s": {
          "type": ["integer", "null"],
          "description": "休息秒数（组间间隔）；无则 null。不单独成页。",
          "minimum": 0
        }
      }
    }
  }
}
```

> 部分模型对 JSON Schema 里 `enum` 含 `null` 支持不佳：若实测失败，改为 `stroke` 等字段只用 string enum，缺省用 JSON `null` 且不要把 `null` 写入 `enum` 数组。实现以「能通过 Provider/Tool 策略校验」为准微调 Schema，**字段语义不得偏离 §9.2**。

#### 9.5.4 调用示意（文档级，非已提交代码）

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy  # 或 ToolStrategy

# swim_plan_schema = 从 JSON 文件加载的 dict，且含 title / description

plan_agent = create_agent(
    model=model,  # 与项目 SiliconFlow 等配置一致
    tools=[],     # 若出计划前已查好数，可不挂工具；需查数可挂只读工具但须确认模型支持 tools+structured 同用
    response_format=ProviderStrategy(swim_plan_schema, strict=True),
)

result = plan_agent.invoke({
    "messages": [{
        "role": "user",
        "content": "根据档案与训练摘要生成今日课表……",
    }]
})
plan = result["structured_response"]  # dict，已按 schema 约束
# 服务端补 plan_id、created_at 后入库；任务 → succeeded
```

若当前 Deep Agent / 硅基模型对 `ProviderStrategy` 不稳定，改用 `ToolStrategy(swim_plan_schema)`，仍 **禁止** 无 schema 的自由输出。

#### 9.5.5 验收标准

1. 计划任务成功时，库中 JSON 能通过上述 Schema（或等价 Pydantic 模型）校验；  
2. 墨水屏只消费校验后的对象，无「从 Markdown 里抠字段」；  
3. Schema 变更与 §9.2 / 设计稿 note 同步更新，并记入本文维护表。

## 10. 异步任务模型（单次 / 趋势 / 计划共用）

### 10.1 状态

```text
queued → running → succeeded | failed
```

屏上映射：

| 任务状态         | UI                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------- |
| queued / running | 转圈；不可进详情 / CTA 不可点                                                      |
| succeeded        | ✓；可进详情或打开计划                                                             |
| failed           | 2.0 可先映射为转圈可重试或静默失败后自动重入队；建议后续加「！」icon（非本版必须） |

### 10.2 触发

| 场景 | 触发 |
|------|------|
| **定时同步后出现新游泳** | **自动**入队单次分析（转圈→✓）；与用户是否打开表盘无关 |
| 用户点列表 ✓ | **只读**已入库报告，**不**创建分析任务、不等模型 |
| 趋势跨度尚无成功报告 | 用户点选该跨度后入队；分析运行页等待；不同步预跑九档 |
| 综合建议要出/重做计划 | 语音触发计划任务；CTA 转圈 |

### 10.3 设备侧行为

- 列表进入时拉「场次 + 状态」；详情只拉已 succeeded 的报告 JSON。
- **未 succeeded 不得进入详情**。
- 墨水屏刷新：回前台刷新状态即可；分析进度在 NAS 侧推进，不靠用户点按触发。

### 10.4 与 Agent 的关系（摘要；细则见《三节目策略》）

- **单次 / 趋势**：Worker **预装数据包** → 分析 agent + Report JSON Schema → 详情页。**不**在分析循环里跑 SQL Agent。旧五主题拆进各节目方法，而非对话点菜。
- **综合建议**：薄对话 + 档案；出计划用独立 plan agent + §9.5 Schema。默认不挂 `ask_swim_database`。
- **混合总 Agent（`create_deep_agent` 主教练主路径）**：**产品主路径废弃**，本分支 `feat/v2-three-programs` 上重构；知识卡可迁移复用。

> SQLite MCP 仍非交互前置。装包用仓库直查即可；MCP 仅为后续平台化选项。

## 11. 端到端故事（验收用）

### 11.1 冷启动看单次报告

1. B 长按开机 → 首页；
2. 进入主菜单 → 焦点「单次分析」→ A 双击；
3. 列表中一场为转圈，一场为 ✓；
4. 焦点移到 ✓ 场次 → A 双击 → 进入详情（详情 UI 就绪后）；转圈场次 A 双击无效。

### 11.2 休眠与唤醒

1. 任意页 B 双击 → 回到首页并休眠、关麦；
2. A 双击 → 主菜单。

### 11.3 综合建议出计划

1. 主菜单进「综合建议」→ 右上「正在聆听...」，正文为引导或档案；
2. 用户说话 → 静音超时或 A 双击确认 → 「正在分析...」→ 「正在回复...」；
3. 若触发计划生成 → CTA 转圈不可点；完成后 CTA 可点；
4. A 双击 → 热身页 → B 单击翻页至主要 / 放松；
5. 语音说「重新生成」→ CTA 再转圈；旧计划是否仍可看：默认 **生成中仍可打开上一份成功计划**（体验更好）；若实现简单可改为生成中完全不可点。**推荐：生成中仍允许打开上一份 succeeded 计划，转圈表示「有新任务在跑」。**（若与「不可点」冲突，以本推荐为准修订 §8.6：仅「从未有成功计划」时生成中不可点。）

> **裁定（写入实现）：**
>
> - 从未有过成功计划且任务进行中 → CTA 不可点；
> - 已有上一份成功计划且正在重新生成 → CTA **仍可点开旧计划**，同时显示转圈表示有新任务；新任务成功后替换为新计划。

### 11.4 返回与关机

- 计划页 A 长按 → 综合建议；再 A 长按 → 主菜单。
- B 长按 → 关机。

## 13. 分阶段落地建议

- CTA 与计划异步及「旧计划可看、新任务在跑」规则。

### 阶段 D — 打磨

- 失败态 icon、弱网提示、耗电与墨水刷新策略；
- 趋势档位是否减负的可用性评估。
