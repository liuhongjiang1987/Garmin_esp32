# 2.0 三节目策略：数据 · 方法 · 报告

> 状态：架构转向规格（`feat/v2-three-programs` 分支）  
> 日期：2026-10-25  
> 关联：`docs/2.0/产品与交互升级方案.md`、`design/untitled.pen`  
> 遗产：`docs/agent-knowledge-cards-v1/`、`agent/skills/swim-coach/`（**主题知识可复用；混合总 Agent 运行时废弃**）

## 0. 总原则

### 0.1 从「一个总 Agent」到「三个节目」

| 1.0（废弃方向） | 2.0 |
|-----------------|-----|
| 热词唤醒 → 一轮对话里混查数、选题、分析、建议 | 主菜单进 **单次分析 / 趋势分析 / 综合建议**，节目边界清晰 |
| 运行时靠主教练 + `ask_swim_database`（SQL 子代理）临时拉数 | **节目任务启动前由服务端装好数据包**；分析/出计划 Agent **默认不跑交互式 SQL Agent** |
| 五主题卡由口语 Agent 每轮自选一张 | 主题知识 **拆进各节目的分析方法**；不是对话里临时点菜 |
| 输出以口语长文为主 | 分析与计划均为 **结构化 JSON**（Schema 约束）+ 短说明，适配 **200×200 / 1.54″ 墨水屏** |

本分支目标：废弃「混合总 Agent」作为产品主路径；代码可暂留只读参考，新功能不往 `create_coach_agent` 总对话里堆。

### 0.2 每个节目必须写清的三件事

1. **数据（Data pack）**：本任务需要哪些字段、从哪装、谁装（Worker / API），**是否允许**再查库。  
2. **方法（Method）**：用哪套分析/生成逻辑（可对应旧主题卡的知识，但入口与输入输出不同）。  
3. **报告（Report）**：结构化指标 + 精炼说明的 Schema 与小屏分页规则。

### 0.3 共同技术约束

- **「数据包」含义（澄清）**  
  - **对本场 / 本窗口而言：数据要完整。** 单次 = 该场 session + **全部 laps** + 档案（+ 方法所需的预计算指标）；趋势 = 窗口内各场汇总字段要齐，不是抽样糊弄。  
  - **相对整库而言：不上传整库。** 不把整个 GarminDB / 无关运动 / 原始 FIT 二进制丢给 LLM。所谓「精简」是 **隐私与边界**（只装本任务需要的完整切片），不是「少给几圈、少给字段」。  
  - 推荐流水线：**代码先算维指标 → 再把「完整切片 + 已算指标」送进 Structured output**；模型主要写短说明与组织报告页，不负责从口语里猜数。
- 结构化输出走 LangChain Structured output（JSON Schema + `ProviderStrategy` / `ToolStrategy`）。  
- 墨水屏：黑白、短句；说明宁缺毋滥。

### 0.4 旧五主题 → 新节目映射（知识层，不是运行时 Skill）

| 旧主题卡 | 主要落入 |
|----------|----------|
| ① 游泳效率 | **单次**维度：效率（指标计算 + 分知识文案） |
| ② 有氧耐力与疲劳漂移 | **单次**维度：耐力/漂移 |
| ③ 动作稳定性与不对称 | **单次**维度：稳定性 |
| ④ 训练负荷与过度疲劳风险 | **趋势**维度：负荷风险 |
| ⑤ 训练周期与进步趋势 | **趋势**维度：周期进步 |
| CSS / 怎么练 / 画像采访 | **综合建议**（对话 + 出计划） |

公用知识（安全、语气）→ 各维度说明的共用规范。

**「下一步」页是什么：** 报告末页的 **一条可执行建议**（例如「下次注意后半程配速」或「恢复日减量」）。可以顺带写「需要课表请去综合建议」，但 **不是** 跳转按钮/路由；小屏也做不了真正深链。产品上就是 **建议文案**，不是导航控件。

### 0.5 已拍板（2026-10-25）

1. 单次默认 **三节捆绑一份报告**（效率 + 耐力 + 稳定性）。  
2. 趋势窗口内场次 **&lt;3** 时：仍出报告，总评标明 **「样本不足」**，弱化或不下强趋势结论。  
3. 综合建议对话保留 **「服务端按需装包」后门**（默认预装摘要；必要时服务端再装一包回灌，不恢复交互式 SQL Agent 主路径）。

### 0.6 模板落地位置（代码）

| 模板 ID | 工程文件 |
|---------|----------|
| `session_bundle_v1` | `agent/src/session_analysis_agent.py` |
| `trend_bundle_v1` | `agent/src/trend_analysis_agent.py` |

报告结构用文件内 Pydantic 模型 + `ToolStrategy` 约束；分知识为模块内常量。  
后续可将每维度公式迁到 `docs/2.0/methods/` 作人工可读副本。

## 1. 节目 A：单次分析

### 1.1 产品一句话与端到端时序

**分析不在用户点进条目时才开始。** 点条目 = **只读已入库报告**；等结果发生在同步之后的后台。

```text
每天定时 Garmin 同步（NAS）
  → 发现新游泳活动 / 新 evidence
  → 立刻创建单次分析任务，状态 = 分析中（列表转圈）
  → Worker 异步：装包 → session_analysis_agent → 报告入库
  → 状态 = 已完成（列表 ✓）
  → 用户在表盘打开「单次分析」：看日期/距离/SWOLF + icon
  → 仅对 ✓ 条目 A 双击：打开已生成的报告详情（秒开，不再跑模型）
  → 转圈条目：不可进详情（静默）
```

列表两态仅：**分析中** / **已完成**。无第三态。  
`python -m src.cli analyze-session` 只是开发机**手动验 Agent**，不是产品路径。

### 1.2 数据（Data pack）

**结论：固定装包，不跑 SQL Agent。**

| 来源 | 内容 |
|------|------|
| 本场 `swim_sessions` 级 | `activity_id`、`start_time`、距离、整场配速（秒与分秒文案）、SWOLF、均/最大心率、总划次、休息时长与休息比等 |
| 本场 `swim_laps` 级 | 每圈距离、用时、配速、心率、划次、泳姿提示、SWOLF、是否休息圈 |
| 档案 | 池长、性别、年龄段、目标、已知伤病/主观备注等（有则带，无则 null） |
| 可选对照（仍非 SQL Agent） | 若方法需要「与自己近期均值比」，由 Worker **预先写入** `baseline` 块（例如近 4 周同泳姿场次均值），分析模型只读包内数字 |

装包责任：异步 Worker 在任务 `running` 时用仓库/SQL **一次性 SELECT**（或现有 `SwimRepository` / evidence 表）拼出 `SessionAnalysisInput`，再交给分析模型。  
**禁止**在分析 Agent 循环里调用 `ask_swim_database` 或 list/schema 式 SQL Agent。

示意输入骨架：

```json
{
  "template_id": "session_default_v1",
  "profile": { "pool_length_m": 25, "goal": "…", "sex": "…", "age": null },
  "session": { "activity_id": "…", "start_time": "…", "distance_m": 1024, "avg_pace_s": 120, "avg_pace_text": "2分00秒/100米", "avg_swolf": 40, "avg_hr": null, "rest_ratio": 0.12 },
  "laps": [ { "lap_index": 1, "pace_per_100m_s": 118, "swolf_derived": 39, "swim_stroke_hint": "freestyle", "is_rest_lap": 0 } ],
  "baseline": { "recent_avg_pace_s": 122, "recent_avg_swolf": 41, "note": "近4周自由泳场次均值；不足3场则为null" }
}
```

### 1.3 分析方法（Method）——不继承对话 Skill

**结论：单次分析不继承旧 `swim-coach` Skill 主循环**（不按轮选题卡、不 `ask_swim_database`、不做口语回合预算）。

正确形态是 **「固定维度 → 代码算指标 → JSON Schema 约束报告」**：

```text
完整本场数据 + 档案
    → 按维度跑确定性指标计算（Python）
    → 得到 metrics 块（数字已算死）
    → 再交给模型：只根据 metrics + 该维度分知识，填 notes / 组织 pages
    → SessionAnalysisReport（Structured output）
```

| 维度 ID | 名称 | 代码侧应算出的例示指标 | 分知识来源（迁入 docs/2.0/methods/，非运行时 skill） |
|---------|------|------------------------|------------------------------------------------------|
| `efficiency` | 效率 | 整场 SWOLF、划次密度、前/后段 SWOLF、与 baseline 差值、刷分嫌疑标记 | 旧主题① / `efficiency.md` |
| `endurance` | 耐力漂移 | 前半 vs 后半配速差%、SWOLF 差、休息圈后首圈质量 | 旧主题② |
| `stability` | 稳定性 | 配速标准差/CV、异常圈列表、泳姿切换次数 | 旧主题③ |

**默认模板名：** `session_bundle_v1` = 上述三维捆绑进 **一份** 报告（已拍板）。  
每维度文档须写清：**输入字段、计算公式、输出 metric 名、说明文案禁忌**——比「继承整份 Skill」更干净。

共用规则（写进分知识，不是 Skill 路由）：

- 无对照时不下「进步/退步」；  
- 无划频/划幅原始数据不编造；  
- 技术瑕疵试探语气；禁止医疗诊断；  
- 配速用已算好的分秒文案。

### 1.4 报告（Report）

目标：**结构化指标 + 精炼说明**，不是口语长文。

小屏分页建议（200×200）：

| 页序 | 标题 | 内容 |
|------|------|------|
| 1 | 本场速览 | 日期、距离、配速、SWOLF（大数字）+ 1 句总评 |
| 2 | 效率 | 2～4 个关键指标 + ≤2 句说明 |
| 3 | 耐力 | 前/后半对比指标 + ≤2 句说明 |
| 4 | 稳定性 | 波动/异常圈指标 + ≤2 句说明 |
| 5 | 下一步 | **一条建议文案**（见 §0.4）；不是页面跳转 |

页数可随缺数据合并（无心率则不出心率行）。续页规则同计划：非末页下三角。  
指标数字以 **代码计算结果为准** 填进 Schema；模型主要生成 `notes` / `one_liner`，避免让模型重算配速。

**输出 Schema 方向（实现时落 JSON Schema 文件）：**

```json
{
  "title": "SessionAnalysisReport",
  "description": "单次游泳分析报告，供200x200墨水屏分页渲染",
  "type": "object",
  "required": ["activity_id", "headline", "pages"],
  "properties": {
    "activity_id": { "type": "string" },
    "template_id": { "type": "string" },
    "headline": {
      "type": "object",
      "required": ["one_liner"],
      "properties": {
        "one_liner": { "type": "string", "maxLength": 48, "description": "一句总评，宜竖屏两行内" },
        "distance_m": { "type": ["number", "null"] },
        "pace_text": { "type": ["string", "null"] },
        "swolf": { "type": ["number", "null"] }
      }
    },
    "pages": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": ["page_id", "title", "metrics", "notes"],
        "properties": {
          "page_id": { "type": "string", "enum": ["overview", "efficiency", "endurance", "stability", "next_step"] },
          "title": { "type": "string", "maxLength": 12 },
          "metrics": {
            "type": "array",
            "maxItems": 4,
            "items": {
              "type": "object",
              "required": ["label", "value"],
              "properties": {
                "label": { "type": "string", "maxLength": 10 },
                "value": { "type": "string", "maxLength": 16 }
              }
            }
          },
          "notes": {
            "type": "array",
            "maxItems": 2,
            "items": { "type": "string", "maxLength": 64 }
          }
        }
      }
    }
  }
}
```

Agent：`create_agent` + `response_format=ProviderStrategy|ToolStrategy(SessionAnalysisReport schema)`，输入仅为 Data pack，输出仅 `structured_response`。

## 2. 节目 B：趋势分析

### 2.1 产品一句话

用户选 **时间跨度** → 进 **分析运行页** → 仅该跨度入队跑 **跨场** 方法 → 完成后进结构化趋势报告（含折线 `charts`）。  
与单次的本质区别：① **输入是时间序列**；② **按点选触发**，不同步预跑九档；新数据同步后作废旧趋势缓存。

### 2.2 数据（Data pack）

**结论：窗口装包，不跑 SQL Agent。**

| 来源 | 内容 |
|------|------|
| 跨度内场次列表 | 每场：日期、距离、配速、SWOLF、休息比、时长、泳姿（若有） |
| 窗口聚合 | 场次数、总距离、周均距离、配速/SWOLF 均值与斜率（可由 Worker 预计算） |
| 档案 | 同单次 |
| 负荷代理 | 可用「场次密度 × 距离 ×（可选心率）」等本地可算代理；无官方 Training Load 则不假装有 |

装包责任：Worker 按跨度 `WHERE start_time BETWEEN …` 一次取出，算好聚合字段写入 `TrendAnalysisInput`。  
圈级明细 **默认不进趋势包**（太大、小屏也用不上）；若某方法强依赖，可另附「代表性一场」摘要，仍预装。

示意：

```json
{
  "template_id": "trend_default_v1",
  "span": "1m",
  "profile": { },
  "sessions": [
    { "activity_id": "…", "start_time": "…", "distance_m": 1500, "avg_pace_s": 118, "avg_swolf": 37 }
  ],
  "aggregates": {
    "session_count": 8,
    "total_distance_m": 12000,
    "pace_slope_s_per_week": -1.2,
    "swolf_slope_per_week": -0.3
  }
}
```

跨度枚举与 UI 九宫格对齐：`1w|2w|3w|1m|2m|3m|6m|9m|1y`。场次过少（如 &lt;3）时报告只能「描述样本不足」，不做强趋势结论。

### 2.3 分析方法（Method）

| 方法 ID | 名称 | 知识来源 | 看什么 |
|---------|------|----------|--------|
| `trend_progress` | 周期进步 | 旧主题⑤ | 配速/SWOLF/距离随时间；进步、平台、回落、伪进步 |
| `trend_load` | 负荷与风险 | 旧主题④ | 量是否突增、密度、恢复债务代理、风险分级（知识版低/中/高） |

**默认模板名：** `trend_bundle_v1` = 进步 + 负荷 两节合成一份报告（文件尚未落盘，见 §0.6）。  
同样：**代码先算窗口指标 → Schema 约束报告**；不继承对话 Skill。

场次 **&lt;3（已拍板）：** 仍生成报告；`headline.one_liner` 或 overview 页明确 **「样本不足」**；progress/load 的强结论降级为描述性语句或注明置信低。

单次维度不原样搬到趋势；跨场统计另定义。

### 2.4 报告（Report）

| 页序 | 标题 | 内容 |
|------|------|------|
| 1 | 区间速览 | 跨度文案、场次数、总距、1 句总评 |
| 2 | 进步 | 配速/SWOLF 方向指标 + ≤2 句 |
| 3 | 负荷 | 密度/风险级 + ≤2 句 |
| 4 | 下一步 | 1 条周期向建议 |
| 5+ | 折线图 | 配速 / SWOLF / 距离：用 `charts.*.points` 画线，用 `charts.*.note` 作图下说明（设计稿如 SWOLF 趋势页） |

Schema：`TrendAnalysisReport` = `headline` + `pages[]`（`overview|progress|load|next_step`）+ 模型只填 `chart_notes`；**落库/下发时服务端合并 `charts`**（数字一律代码算，禁止模型编造点列）。`span` 必填。

前端渲染约定（`charts`）：

```json
"charts": {
  "swolf": {
    "key": "swolf",
    "title": "SWOLF趋势分析",
    "unit": "",
    "lower_is_better": true,
    "note": "近6次整体下降，效率在变好",
    "points": [
      {"index": 1, "activity_id": "...", "date": "2026-09-05", "value": 46.0}
    ]
  },
  "pace": {
    "key": "pace",
    "title": "配速趋势分析",
    "unit": "s/100m",
    "lower_is_better": true,
    "note": "...",
    "points": [
      {"index": 1, "activity_id": "...", "date": "2026-09-05", "value": 92.0, "value_text": "1'32\""}
    ]
  },
  "distance": {
    "key": "distance",
    "title": "距离趋势分析",
    "unit": "m",
    "lower_is_better": false,
    "note": "...",
    "points": [
      {"index": 1, "activity_id": "...", "date": "2026-09-05", "value": 1200.0}
    ]
  }
}
```

- 点列按时间升序，默认最多 **6** 点（取窗口末段，对齐墨水屏折线稿）。
- 画线用 `value`；配速屏显可用 `value_text`。
- 缺字段的场次该系列可少点，前端按现有 `points` 连线即可。

## 3. 节目 C：综合建议

### 3.1 产品一句话

进入即听麦（无热词）→ 维护 **持久画像与目标** → 语音短轮次 → 异步生成 **结构化训练计划**（热身/主要/放松）。  
这是旧「总 Agent」里 **CSS/怎么练/采访/出主意** 的归宿，但交付物以 **计划页** 为主，口语为辅。

### 3.2 数据（Data pack）

| 阶段 | 数据 | 是否 SQL Agent |
|------|------|----------------|
| 进页 | 持久档案（年龄、身高、体重、性别、目标、池长等） | 否，读档案库 |
| 语音轮 | ASR 文本 + 当前档案 + **预装近期摘要卡** | 默认预装；**不挂交互式 SQL Agent** |
| 出计划任务 | 档案 + 诉求摘要 + 摘要卡 +（可选）报告 headline | Worker 装包 + 计划 JSON Schema |
| 按需装包（已拍板后门） | 对话中发现摘要不够时，**服务端**按意图再查一次、装包回灌本轮上下文 | 仍不是模型自己写 SQL；禁止恢复 `ask_swim_database` 主路径 |

旧 `ask_swim_database` 仅可作迁移期调试，不作为产品依赖。

### 3.3 方法（Method）

| 能力 | 做法 |
|------|------|
| 画像采集/更新 | 语音槽位填充 → `save_profile_fields` 同类持久化；二次进入展示已有字段 |
| 短回复 | 轻量对话模型/Agent；状态机：聆听 / 分析 / 回复；正文区刷新，不做聊天气泡流 |
| 出计划 / 重生成 | 独立 plan agent；**JSON Schema 强制**（产品方案 §9.5）；语音触发，无额外按键 |
| CSS / 配速区 | 若保留，作为综合建议内工具或计划生成前的档案字段，**不**放进单次/趋势默认报告 MVP |

旧 skill 的「每轮主循环、只选一张主题卡、综合题只选题」→ **不再作为本节目主循环**。综合建议不负责五主题深度分析（那是单次/趋势的事）；用户问「我最近游得怎么样」可：**一句话引用已有报告结论** 或引导去单次/趋势节目。

主报告 = **训练计划结构化页**（已有设计契约与 Schema 方向）。
